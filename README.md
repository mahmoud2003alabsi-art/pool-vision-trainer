# Pool Vision Trainer — ترينر بلياردو بالرؤية الحاسوبية (C++17)

أداة تحليل وتدريب مستقلة لطاولة البلياردو (ثمانية كرات): تكتشف الكرات من صورة الطاولة
تلقائياً، ثم تحسب أفضل الضربات الممكنة — ضربات مباشرة بكرة الشبح، وضربات بنك/كيت حتى
حوافّ متعددة بطريقة المرايا (طي الطاولة) — وتُخرج صورة مشروحة بالخطوط + تقرير JSON كامل.

**صفر اعتماديات خارجية**: لا OpenCV ولا أي مكتبة ثالثة غير ملفّي stb العامين (مضمّنان).
البناء = CMake + أي مترجم C++17، وهذا يجعل الـ CI على GitHub يعمل بدون تثبيت أي حزمة.

## ماذا تخرج لك الأداة؟

| المخرج | الوصف |
|---|---|
| `*_annotated.png` | الصورة الأصلية + خط التصويب، دائرة كرة الشبح، مسار الكرة الهدف نحو الجيب، نقاط الارتداد على الحواف، خط المماس (قاعدة 90°)، وتسمية كل كرة برقمها |
| `*_result.json` | كل الكرات المكتشفة (نوعها، لونها، رقمها المرجّح، مركزها بالبكسل وبالإحداثيات المنطقية) + كل الضربات الممكنة مع زاوية القطع والثقة ومساراتها |
| طباعة في الطرفية | ملخص أفضل الضربات: النوع، الكرة الهدف، الجيب، زاوية القطع، درجة الثقة |

## أنواع الضربات المحسوبة

1. **Direct (مباشرة)**: لكل كرة هدف × كل جيب يُحسب موضع **كرة الشبح**
   `ghost = T − normalize(P − T) × 2R`، ثم زاوية القطع بين خط التصويب واتجاه الجيب،
   وفحص الانسداد على المسارين (البيضاء→الشبح والهدف→الجيب)، وتقدير الثقة
   (زاوية أقل + مسافات أقصر = ثقة أعلى). مع خط المماس لقاعدة الـ 90°.
2. **Bank (بنك)**: البيضاء تضرب الهدف فيرتجف عن حافة/حواف ثم يدخل الجيب —
   يُحل بطريقة **طي الطاولة**: انعكاس الجيب عبر الحواف بالترتيب العكسي، التصويب نحو
   الصورة المطوية، ثم "فك" المسار نقطة بنقطة مع التحقق أن كل ارتداد يقع داخل الحافة
   وخارج أفواه الجيوب.
3. **Kick (كيت)**: البيضاء ترتجف عن الحواف أولاً ثم تضرب الكرة الهدف — نفس الحلال
   مع الهدف بدل الجيب. يفحص الانسداد على كل قطعة من المسار.

الترتيب الافتراضي للحواف حتى حافتين؛ يمكن رفعه بـ `--max-rails 3`.

## بنية المشروع

```

  jsonw.hpp    كاتب JSON صغير

```

## كيف يعمل الكشف البصري؟

1. تحويل الصورة إلى HSV وبناء قناع القماش الأخضر (نافذة تدرّج اللون قابلة للضبط).
2. أكبر مكوّن متصل للقناع = مستطيل الطاولة (تصحيح الإحداثيات لاحقاً).
3. داخل المستطيل: "بكسلات الكرات" = كل ما ليس قماشاً → مكوّنات متصلة (Blobs).
4. الوسيط لمساحة الكتل (باستبعاد الجيوب أولاً حتى لا تشوّه الإحصاء) = مساحة الكرة
   → نصف القطر؛ تُقبل الكتل القريبة من هذا الحجم فقط.
5. استبعاد الكتل المتمركزة عند مواضع الجيوب الستة (زوايا + منتصفا الضلعين).
6. تصنيف كل كرة من إحصائيات HSV داخلها:
   - نسبة سوداء عالية → الكرة السوداء (8)
   - نسبة بيضاء عالية جداً → البيضاء (Cue)
   - نسبة بيضاء متوسطة → مخططة (9–15) وإلا ممتلئة (1–7)
   - تدرّج اللون السائد (Hue) → الاسم والرقم المرجّح (أصفر=1/9، أزرق=2/10، أحمر=3/11،
     بنفسجي=4/12، برتقالي=5/13، أخضر=6/14، خمري=7/15)
7. إسقاط المراكز على إحداثيات الطاولة المنطقية (تحويل خطي من مستطيل القماش).

## البناء محلياً

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure     # اختبارات الحلال
./build/pool-trainer demo --out demo_output    # ديمو كامل من الصفر
```

المتطلبات: CMake 3.14+ ومترجم C++17 (GCC/Clang/MSVC). لا غير ذلك.

## الاستخدام

```bash
# توليد طاولة اصطناعية + كشف + حل + صورة مشروحة + JSON
./build/pool-trainer demo --out demo_output

# تحليل أي صورة طاولة من الأعلى (PNG/JPG/BMP)
./build/pool-trainer analyze mytable.png --out out --table 900x450 --max-rails 2 --top 3
```

| الخيار | المعنى |
|---|---|
| `--out DIR` | مجلد المخرجات (افتراضي `output`) |
| `--table WxH` | أبعاد الطاولة المنطقية للإسقاط (افتراضي 900x450) |
| `--max-rails N` | أقصى عدد حواف لحلول البنك/الكيت (افتراضي 2، يدعم حتى 3) |
| `--top N` | عدد الضربات المرسومة على الصورة (افتراضي 3) |
| `--seed N` | بذرة الضوضاء في الديمو |

## التجميع التلقائي على GitHub (Actions)

المشروع جاهز للدفع كما هو — الـ workflow `.github/workflows/ci.yml` سيعمل تلقائياً:

1. أنشئ مستودعاً جديداً على GitHub ثم:

```bash
cd pool-vision-trainer
git init                       # (منجز مسبقاً مع كوميت أولي)
git remote add origin https://github.com/<USER>/<REPO>.git
git push -u origin main        # أو: gh repo create --public --source=. --push
```

2. افتح تبويب **Actions** في المستودع — سترى "CI" يبني المشروع على **لينكس وويندوز**
   ويشغّل الاختبارات ويستخرج ديمو كامل (طاولة مولّدة → كشف → حل → صور مشروحة).
3. نزّل المخرجات من قسم **Artifacts** بعد انتهاء التشغيل:
   - `pool-trainer-Windows` — `pool-trainer.exe` (محلل الصور) + `pool-overlay.exe`
     (الأوفرلاي الحيوي) + نتائج الديمو (طاولة مولّدة، صور مشروحة، تقارير JSON)
   - `pool-trainer-Linux` — نسخة لينكس من المحلل + نتائج الديمو
4. لتشغيل الـ Action يدوياً في أي وقت: زر **Run workflow** في صفحة Actions.
   ولتشغيل المحلل بعد التنزيل: `pool-trainer demo --out demo` ثم افتح
   `demo/table_annotated.png`.

## المحاكاة الفيزيائية الكاملة (simulate)

`pool-trainer simulate` يجيب على سؤال "ماذا سيحدث بالضبط؟": يكشف الطاولة
والكرات، يقرأ اتجاه التصويب (خط اللعبة الأبيض إن كان ظاهراً، وإلا أفضل ضربة
محلولة، أو `--dir` يدوياً)، ثم يشغّل محاكاة فيزيائية كاملة ويطبع كل شيء:

```bash
pool-trainer simulate لقطة.png --out نتيجة                    # قوة تلقائية
pool-trainer simulate لقطة.png --power 0.6 --contact 0,-0.6   # ضربة مرتدة
pool-trainer simulate لقطة.png --dir 45 --contact 0.5,0.8     # اتجاه يدوي + follow
```

- `--contact DX,DY`: نقطة الضرب على الكرة البيضاء بوحدات نصف قطرها:
  `+Y` = follow (أمامي)، `-Y` = draw (ارتداد للخلف)، `X` = انجليزية جانبية.
- بدون `--power` يُحسب **أدنى قوة تُدخل الكرة المستهدفة** (auto-power).
- المخرجات: مسارات كل الكرات بألوان مختلفة على `<image>_sim_annotated.png` +
  مواقع التوقف النهائية + الكرة المُدخلة والجيب + تحذير خدش (scratch) +
  `<image>_sim_result.json` بكل الأحداث (تماسات، كوسون، جيوب).
- الفيزياء: احتكاك تدحرجي، تصادمات مرنة بخط المراكز مع **كشف تماس مستمر**
  (إرجاع الزوج لنقطة التماس الدقيقة داخل الخطوة — بدونها تنحرف الكرة 2-3°
  وتفوت الجيب)، ارتداد كوسون بمعامل ارتداد، أثر follow/draw بعد التلامس
  وانجليزية على الارتدادات، والتقاط في الجيوب بنصف قطر الفم.
- تقرير الاعتماد على مسح الريبوهات وتقنيات المجال: انظر [RESEARCH.md](RESEARCH.md).

## الـ Overlay الحيوي فوق اللعبة (ويندوز — Google Play Games)

`pool-overlay.exe` نافذة شفافة قابلة للنفاذ بالنقر تتابع نافذة اللعبة: تلتقطها
عبر `PrintWindow` (بدون لقطات شاشة ولا تظهر خطوطها في الالتقاط)، تكشف الطاولة
والكرات بالكشف التكيفي (يعمل على قماش 8 Ball Pool الرمادي الداكن)، ويرسم فوق
اللعبة بوضعين:

- **أثناء التصويب** (خط اللعبة الأبيض ظاهر): يقرأ اتجاه تصويبك الحالي، يشغّل
  المحاكاة الفيزيائية بأدنى قوة تُدخل، ويرسم **التوقع الكامل**: امتداد خطك،
  مسار كل كرة بعد الضربة، حلقات مواقع التوقف النهائية، ووميض الجيب (أصفر =
  إدخال، أحمر = خدش cue) — فتعرف نتيجة ضربتك قبل أن تُطلقها.
- **عند السكون**: أفضل الضربات المحلولة — خط التصويب الأبيض، دائرة الكرة
  الشبحية، المسار الأصفر إلى الجيب، ونقطة الجيب الصفراء.

### قائمة إعدادات كاملة بالماوس (بدون تيرمنال وبدون مفاتيح)

عند تشغيل البرنامج تظهر قائمة **Settings** بأسلوب ImGui (شريط عنوان قابل
للسحب مع زر X، تبويبات يسارية، checkbox/slider/combo):

| التبويب | المحتوى |
|---|---|
| **AIM** | إظهار الخطوط، معاينة المحاكاة أثناء التصويب، عدد الجدران، عدد الضربات |
| **DETECT** | إزالة خط التصويب، حجم الكرة (0 = تلقائي)، تسامح القماش S/V |
| **TABLE** | قوالب الطاولة (8BP / عام / مدمج / سنوكر)، منطقة يدوية + 4 منزلقات، عرض/ارتفاع مخصص |
| **GAME** | اختيار نافذة اللعبة من قائمة النوافذ المفتوحة + زر تحديث |
| **MISC** | FPS، زر **حفظ الإعدادات** (pool-overlay.ini)، زر خروج |

- **النقر يمر للعبة** في كل مكان خارج لوحة القائمة (تمرير شفافية ديناميكي).
- القائمة قابلة للسحب من شريط العنوان، والقيم تعمل فوراً بدون إعادة تشغيل.
- لا تيرمنال إطلاقاً: البرنامج يعمل بنافذة فقط؛ كل الرسائل في
  `pool-overlay.log` بجانب البرنامج، وشريط حالة صغير أعلى الشاشة عند إغلاق
  القائمة: `balls=6 shots=4 aim=ON pot=1 …`.

### يعمل مع أي لعبة تلقائياً — حتى الطاولات المرسومة بمنظور

بدون أي إعداد يبحث الأوفرلاي عن نافذة اللعبة بنفسه: يفحص كل النوافذ
المفتوحة (أولاً العناوين التي فيها pool/billiard/billar/snooker/بليارد)، ثم
يجرب التقاط كل نافذة مرشحة ويختار أول نافذة يظهر فيها مستطيل طاولة سليم —
أغلق لعبة وافتح غيرها وسيتابع العمل. تبويب **GAME** يتيح تثبيت نافذة محددة
يدوياً عند الحاجة.

**الطاولات بمنظور (شبه منحرف)** — مثل Pool Club على Poki — مدعومة الآن
بدقة: الكشف يلائم قماش اللعبة كرباعي (quad) بأربعة زوايا ويحسب الخريطة بين
المنطق والبكسل بخريطة خطية ثنائية (bilinear) بدل التمدد المستطيلي، فتقع
الخطوط والدوائر على مقاس الطاولة والكرات الحقيقية حتى لو ضاقت الطاولة من
الأعلى. كرة الضرب تُميّز بالعزلة: البيضاء الوحيدة في مساحة مفتوحة هي cue
حتى لو وُجدت كرات بيضاء داخل عنقود، وحجم الكرة يُقدَّر بالمئين 25 لمناطق
الكتل المندمجة فلا تنتفخ الدوائر.

### نمط المدرب الكلاسيكي (شكل صور aim trainer الشهيرة)

الأوفرلاي يرسم الآن المشهد الكامل المعروف من صور مدربي 8 Ball Pool:

- **خط إرشادي رفيع لكل كرة** لها ضربة ممكنة: خط أبيض من كرة الضرب إلى نقطة
  التماس (ghost)، حلقة أشباح عند التماس، وخط أصفر مع سهم يصل إلى الجيب
  المستهدف (والضربات الخاطئة عبر الحواف بلون سماوي).
- **أفضل 3 ضربات** تُرسم سميكة: مسار كرة الضرب كاملاً بما فيه ارتدادات
  الحواف، حلقة الجيب الحمراء + النقطة الصفراء، وسهم الظل (tangent) يبين
  اتجاه خروج كرة الضرب بعد التماس، مع تسمية لكل ضربة (CUT/CONF).
- **حدود الطاولة** بدقة المنظور + دوائر الكرات بأحجامها الحقيقية.
- كل ذلك يُطوى من تبويب AIM عبر خيار **Trainer lines (all balls)** أو
  سطر الأوامر `--no-trainer` إن أردت الرسم المينيمالي القديم.

### الاستقرار (anti-jitter)

- كل إطار يُركَّب في ذاكرة خارجية ثم يُعرض بمرة واحدة (double buffer):
  لا وميض ولا رعش من الرسم المباشر فوق نافذة color-key.
- إطار الطاولة والمضلع الرباعي ونصف قطر الكرات ومراكزها تُجانَس زمنياً
  (EMA) مع snap فوري للحركات الحقيقية، وتُمسك الكرات المفقودة لحظياً بضع
  إطارات حتى لا تطفش الخطوط — انظر `include/pool/stabilize.hpp`.
- `SetWindowPos` لا يُستدعى إلا عند تغيّر مستطيل اللعبة فعلاً.

### التعرف على كرات 8 Ball Pool (اللوحة المقاسة)

- اللوحة معايرة على قيم مقاسة من لقطات 8BP الحقيقية: الأصفر hue 41..62
  (الكرة 1/9)، البرتقالي 15..41 (5/13)، البنفسجي 255..345 (4/12)،
  والخمرية حمراء داكنة v<0.55 (7/15) — واللون يُقرأ من **البكسلات
  المضاءة** للكرة (النصف المظلل يقرأ 10‑25° نحو الأحمر).
- لباد 8BP الأزرق المتدرج (المنتصف المضاء s~0.43 مقابل الحواف s~0.88)
  يُعاد عتبته تكيفياً حول وسيطات اللباد نفسه، مع بوابة نمو صارمة (≤3%
  لكل جانب) حتى لا يتسرب القناع إلى محيط الصفحة.
- قرص الشبح الشفاف الذي ترسمه اللعبة على نقطة التلامس لا يسرق هوية
  الكرة البيضاء: كسر التعادل بالنقاء + صلاحية الـhue (قرص بلا بكسلات
  ملونة لا يصنع رقماً زائفاً) + إنقاذ متعدد الأقراص يفصل cue عن الكرة
  الهدف المرسوم فوقها.

### العصا والقوة (الزاوية والقوة لحظياً)

- `findCueStick`: مسح أشعة سميكة (3 إزاحات عمودية) من الكرة البيضاء
  عن أعواد خشبية (hue 12..55) بحدود الصورة كاملة — العصا في 8BP تمتد
  فوق اللباد إلى رأس النافذة. يعطي زاوية التصويب **ومسافة السحب**
  (القوة) أثناء السحب قبل تحرك أي كرة.
- `findPowerSlider`: شريط القوة البرتقالي يسار الطاولة مع مقبضه
  الأفتح (كسر التشبع هو البصمة) — يعطي القوة 0..1؛ وإن لم يظهر مقبض
  واضح يعيد -1 (مجهول) ولا يختلق رقماً.
- HUD يعرض `pow=%` و`S` عند رصد العصا، وسهم سماوي يرسم اتجاه التصويب
  من العصا عندما لا يرسم المسار الأبيض؛ ومعاينة التصويب تستخدم اتجاه
  العصا عند غياب خط اللعبة.
- عندما تكون نافذة اللعبة مغطاة (نافذة أخرى فوقها) يتوقف التحليل
  تلقائياً — BitBlt لنافذة مغطاة يلتقط ما فوقها وكان يرسم خطوطاً
  خاطئة على النافذة المغطية.

### ثبات هوية الكرة البيضاء

الكرة المخططة التي وقعت على وجهها الأبيض تشبه cue تماماً في المركز؛
المُصنِّف يقيس الآن **حلقة الحافة** (0.68R..0.95R): حافة الكرة البيضاء
بيضاء بالكامل، وحافة الكرة المخططة ملونة بشريطها — فلا يمكن أن تُسرق
المخططة هوية الكرة البيضاء في التصنيف ولا في تصويت العزل ولا في مسار
إنقاذ cue، وهذا مغطى باختبارات.
- أمر `analyze` يرسم الصورة التعليمية بنفس النمط بالضبط، فما تراه في
  `*_annotated.png` هو ما سيظهر مباشرة فوق اللعبة.

**pool-overlay.ini** (بجانب البرنامج): window (auto أو عنوان محدد)، tableW/H،
rails، shots، fps، guides، aimPreview، ballR، feltTolS/V، stripLines،
manualRect، rectX0/Y0/X1/Y1.

**الضبط من لقطة** (اختياري): `pool-trainer tune لقطة.png --out نتيجة --save`
يويّد ini جاهزاً للنسخ بجانب البرنامج، مع تجاوزات `--rect --ballr --tols
--tolv --no-strip`.

**التقاط محصّن**: PrintWindow ثم fallback تلقائي لالتقاط الشاشة عند الأطر
السوداء (نوافذ GPU المحمية)، ومع SetProcessDPIAware للبكسلات الفيزيائية.

### التشغيل

```bat
pool-overlay.exe
:: أو بخيارات مخصصة:
pool-overlay.exe --window "8 Ball Pool" --table 900x530 --shots 1 --fps 12
```

- شغّل لعبة 8 Ball Pool عبر Google Play Games على الكمبيوتر أولاً؛ الأوفرلاي
  يجدها تلقائياً بالعنوان ويلاحق تحركها.
- مفاتيح التشغيل: **Insert** إخفاء/إظهار واجهة القائمة وشريط الحالة
  (الخطوط تبقى مرسومة)، **X** خروج نهائي مع حفظ الإعدادات، **A** معاينة
  التصويب، **1..5** عدد الضربات، **F7/F8** نصف قطر الكرات، **[ / ]**
  حساسية الكشف، **R + الأسهم** المستطيل اليدوي، **F10** حفظ فوري.

### خيارات سطر الأوامر

| خيار | المعنى |
|---|---|
| `--window "..."` | جزء من عنوان نافذة اللعبة (افتراضي "8 Ball Pool") |
| `--table WxH` | الحجم المنطقي للطاولة (افتراضي 900x530 مطابق لنسبة لوح اللعبة) |
| `--rails N` | أقصى عدد ارتدادات للحلول (0-3، افتراضي 2) |
| `--shots N` | رسم أفضل N ضربات (1-5، افتراضي 1) |
| `--fps N` | معدل التحليل في الثانية (2-30، افتراضي 12) |

### ملاحظات تشغيلية

- عناصر الواجهة داخل الطاولة (عملة الذهب، حلقة Golden Shot) قد تظهر ضمن
  الكشف — خطوط التصويب تُحسب من الكرات الحقيقية، وتجاهل هذه العناصر طبيعي.
- على الأجهزة الضعيفة استخدم `--fps 8` لتخفيف الحمل.
- الكشف التكيفي نفسه يعمل أيضاً في المحلل: `pool-trainer analyze لقطة.png
  --out نتيجة` يفهم لقطة اللعبة الرمادية مباشرة (يُفضّل قص منطقة الطاولة أولاً).

## حدود الأداة وإخلاء مسؤولية

- `pool-trainer` يحلل **صوراً وملفات**، و`pool-overlay.exe` (ويندوز) نافذة
  تحليل شفافة فوق نافذة اللعبة على Google Play Games للكمبيوتر — كلاهما للتدريب
  والتحليل والتعلم.
- الكشف مُعايَر لصور الطاولة من الأعلى (لقطات لعبة، صور مولّدة). للصور الفوتوغرافية
  المائلة أو الإضاءة الغريبة قد تحتاج ضبط `DetectOptions` (نافذة لون القماش، العتبات).
- تصنيف الرقم "مرجّح" من اللون + النوع: التمييز النهائي بين كرتين بنفس اللون
  (مثل 1 و9) يعتمد على نمط التخطيط (ممتلئة/مخططة) كما في الكاشف.
- استخدام أي أداة مساعدة أثناء مباريات أونلاين ضد لاعبين آخرين مخالف لشروط خدمة
  الألعاب (مثل 8 Ball Pool) وقد يؤدي لحظر الحساب — استخدم هذه الأداة للتدريب
  وتحليل الصور والتعلم فقط.
